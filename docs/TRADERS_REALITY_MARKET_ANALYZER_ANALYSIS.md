## 1. Что это такое

`market_analyzer.py` — это Streamlit-приложение для ручного анализа крипторынка. В основе лежит набор индикаторов, взятых из торговой системы **Traders Reality** (оригинально написанной на PineScript для TradingView). Файл реализует полный стек инструментов: загрузку данных, расчёт индикаторов, систему сигналов и сканер алертов по 200+ монетам.

Ключевой инсайт: **файл описывает готовую, проверенную трейдерами торговую систему**, объединяющую несколько независимых методик в один составной сигнал.

## 2. Индикаторы и методики — подробный разбор

### 2.1. EMA Stack (Стек скользящих средних)

**Периоды:** EMA 5, 13, 50, 200, 800

```python
df["EMA5"]   = calc_ema(df["Close"], 5)
df["EMA13"]  = calc_ema(df["Close"], 13)
df["EMA50"]  = calc_ema(df["Close"], 50)
df["EMA200"] = calc_ema(df["Close"], 200)
df["EMA800"] = calc_ema(df["Close"], 800)
```

**Сигнал бычьего стека:**
```
EMA5 > EMA13 > EMA50 > EMA200  →  +2 балла
```
**Медвежий стек:**
```
EMA5 < EMA13 < EMA50 < EMA200  →  -2 балла
```

**Смысл:** Когда все EMA выстраиваются в одном порядке — рынок в сильном тренде. Это классический momentum-фильтр. Набор 5/13/50/200 — стандарт Traders Reality, где 5 и 13 — краткосрочный импульс, 50 — среднесрочный тренд, 200 — глобальный тренд, 800 — только для визуализации.

**Дополнительно — EMA Cross:**
```
EMA5 пересекает EMA13 снизу вверх  →  +1 балл (momentum-подтверждение)
EMA5 пересекает EMA13 сверху вниз  →  -1 балл
```

### 2.2. PVSRA (Price, Volume, Spread, Range Analysis)

Это центральная идея системы Traders Reality. Метод анализирует силу каждой свечи через комбинацию объёма и спреда.

```python
def calc_pvsra(df: pd.DataFrame) -> pd.Series:
    avg_vol = vol.rolling(10).mean()
    max_spread_vol = (spread * vol).rolling(10).max()

    cond_rv = (vol >= avg_vol * 2) | (spread * vol >= max_spread_vol)   # Ring Volume
    cond_bv = (vol >= avg_vol * 1.5) & ~cond_rv                          # Big Volume
```

**Классификация свечей:**

| Метка | Условие | Смысл |
|-------|---------|-------|
| `green` | Ring Volume + бычья свеча | Сильная бычья активность маркетмейкера |
| `red` | Ring Volume + медвежья свеча | Сильная медвежья активность маркетмейкера |
| `blue` | Big Volume + бычья свеча | Умеренно повышенная бычья активность |
| `violet` | Big Volume + медвежья свеча | Умеренно повышенная медвежья активность |
| `gray_up` / `gray_dn` | Обычный объём | Нейтральная свеча |

**Вклад в сигнал:**
- `green` или `blue` → +1 балл (и дополнительно `green` → ещё +1)
- `red` или `violet` → -1 балл (и дополнительно `red` → ещё -1)

**Смысл:** PVSRA — это метод определения действий крупных игроков (маркетмейкеров). Ring Volume — объём в 2× выше среднего или максимальное произведение спреда и объёма за 10 баров. Это называется "векторами" в системе TR.

### 2.3. Pivot Points (Классические дневные пивоты)

```python
daily["PP"]  = (high + low + close) / 3
daily["R1"]  = 2*PP - low
daily["S1"]  = 2*PP - high
daily["R2"]  = PP + (high - low)
daily["S2"]  = PP - (high - low)
daily["R3"]  = high + 2*(PP - low)
daily["S3"]  = low  - 2*(high - PP)
daily["M1"]  = (PP + R1) / 2
daily["M2"]  = (PP + S1) / 2
```

Пиvoты рассчитываются по дневным свечам и применяются к следующему дню (`.shift(1)`).

**Вклад в сигнал:**
```
Цена выше PP  →  +1 балл
Цена ниже PP  →  -1 балл
```

**Смысл:** PP — центр гравитации дня. Нахождение выше/ниже PP — базовый фильтр направления.

---

### 2.4. ADR — Average Day Range (Средний дневной диапазон)

```python
def calc_adr(df: pd.DataFrame, length: int = 14) -> pd.Series:
    daily_range = df["High"].resample("D").max() - df["Low"].resample("D").min()
    return daily_range.rolling(length).mean()
```

**Применение — ADR Exhaustion (истощение диапазона):**
```python
adr_used_up   = (close - day_low)  / adr   # насколько дневной диапазон использован снизу
adr_used_down = (day_high - close) / adr   # насколько диапазон использован сверху

# Если использовано >85% ADR — движение на исходе:
score -= (adr_used_up   > 0.85)  # цена высоко в дневном диапазоне → осторожно с лонгом
score += (adr_used_down > 0.85)  # цена низко в дневном диапазоне → осторожно с шортом
```

**Смысл:** ADR — это фильтр "истощения". Если цена прошла 85% от своего среднего дневного диапазона — входить в направлении тренда поздно. Это защита от входов на экстремумах дня.

### 2.5. Weekly Levels — M0 и M5

```python
def calc_weekly_levels(df: pd.DataFrame):
    weekly_high = df["High"].resample("W").max().shift(1)  # M5 — HIGH прошлой недели
    weekly_low  = df["Low"].resample("W").min().shift(1)   # M0 — LOW прошлой недели
```

- **M5** = максимум предыдущей недели → уровень сопротивления
- **M0** = минимум предыдущей недели → уровень поддержки

**Смысл:** В системе Traders Reality недельные уровни — это ключевые зоны, где крупные игроки исторически проявляют активность. Пробой M5 вверх — признак силы. Отскок от M0 — потенциальная зона входа в лонг.

---

### 2.6. Yesterday High / Low (Уровни прошлого дня)

```python
yday_high = df["High"].resample("D").max().shift(1)
yday_low  = df["Low"].resample("D").min().shift(1)
```

Вспомогательные уровни — не участвуют в скоре сигнала, только визуализация. Но в контексте стратегии важны как ближние уровни поддержки/сопротивления.

## 3. Система сигналов

### 3.1. Составной скор

Все факторы складываются в единый `signal_score` на каждый бар:

```
signal_score = 0
+ EMA Bull Stack     → +2
- EMA Bear Stack     → -2
+ PVSRA Bull (green/blue) → +1
+ PVSRA Strong Bull (green) → +1 (итого до +2 за green)
- PVSRA Bear (red/violet)   → -1
- PVSRA Strong Bear (red)   → -1 (итого до -2 за red)
+ цена > PP  → +1
- цена < PP  → -1
- ADR Up Exhaustion (>85%)  → -1
+ ADR Down Exhaustion (>85%) → +1
+ EMA5 пересекает EMA13 снизу → +1
- EMA5 пересекает EMA13 сверху → -1
```

**Максимальный теоретический скор: ~+8 / -8**

### 3.2. Интерпретация скора

| Диапазон | Сигнал |
|----------|--------|
| ≥ +4 | **STRONG LONG** |
| +2 .. +3 | **LONG** |
| -1 .. +1 | **NEUTRAL** |
| -2 .. -3 | **SHORT** |
| ≤ -4 | **STRONG SHORT** |

## 5. Применимость к smc-bot — новая стратегия

### 5.1. Концепция новой стратегии

Предлагаемое название: **`bt_traders_reality`** или **`bt_tr_pvsra`**

Стратегия объединяет методику Traders Reality с уже существующей архитектурой smc-bot:

**Таймфреймная логика:**
- **HTF (4H или Daily):** Определение глобального тренда через EMA Stack (EMA50 > EMA200 = бычий рынок)
- **LTF (1H или 15m):** Поиск точки входа — PVSRA green-вектор + цена выше PP + ADR не истощён

### 5.2. Логика входов

**Условия для LONG:**
1. HTF EMA Stack бычий: `EMA50 > EMA200` на 4H
2. LTF: `signal_score >= 2` (LONG или STRONG LONG)
3. LTF: PVSRA = `green` или `blue` (бычий вектор объёма)
4. LTF: цена выше дневного PP
5. LTF: ADR Exhaustion < 70% (не входим у вершины дня)
6. Опционально: цена у M0 (недельная поддержка) — приоритетная зона

**Условия для SHORT:**
1. HTF EMA Stack медвежий: `EMA50 < EMA200` на 4H
2. LTF: `signal_score <= -2`
3. LTF: PVSRA = `red` или `violet`
4. LTF: цена ниже дневного PP
5. LTF: ADR Exhaustion < 70% по шорту
6. Опционально: цена у M5 (недельное сопротивление) — приоритетная зона

### 5.3. Stop Loss

- **Ближний SL:** ниже `M0` (для лонга) / выше `M5` (для шорта)
- **Дневной SL:** ниже дневного `S1` или `S2`
- **Альтернатива:** % от ATR или фиксированный % от ADR

### 5.4. Take Profit

- **TP1:** Дневной `R1` (пивот)
- **TP2:** Дневной `R2`
- **TP3:** Недельный `M5` (для лонга)
- Частичный выход 50% на TP1, остаток ведём до TP2/TP3

### 5.5. Фильтры и защиты

| Фильтр | Реализация |
|--------|-----------|
| ADR Exhaustion | Не входить если ADR Used > 70-85% |
| Trend alignment | Входить только по направлению HTF EMA Stack |
| Weekly level proximity | Избегать входов на M5 в лонг / M0 в шорт (могут быть разворотными) |
| PVSRA качество | Для лонга предпочитать `green` > `blue`, для шорта `red` > `violet` |

## 8. Приоритет и риски реализации

**Высокий потенциал:**
- PVSRA — редкий и мощный индикатор, не входит в стандартный набор backtrader
- Составной скор — даёт чёткие числовые критерии входа, легко тестировать

**Риски:**
- PVSRA требует реальных данных по объёму с Binance (не все таймфреймы/пары одинаково надёжны)
- Дневные пиvoты требуют корректной агрегации OHLCV по UTC vs локальному времени — нужна аккуратная реализация
- ADR на истории может быть нестабильным для малоликвидных пар

**Рекомендация:** Начать с бэктеста на BTC/ETH 1H, настроить параметры, затем расширять на другие пары.
